# AETHER — Stage 4A Technical Report: Deforestation Pixel & Region Analysis

---

## 1. Objective

Stage 4A of the **AETHER Deforestation Detection Module** executed quantitative pixel-level, spatial connected-component, small-noise size distribution, and baseline engineering severity analysis on the predicted binary deforestation masks generated by the locked Stage 2B Early-Fusion Classical U-Net model (`models/unet.py`, ~31.04M parameters) operating at the primary locked threshold ($t = 0.25$).

The objective of Stage 4A is to convert raw binary segmentation outputs into structured spatial features (pixel counts, percentages, connected component counts, bounding boxes, centroids, and severity categories) ready for backend API consumption and frontend dashboard visualization.

---

## 2. Input and Model Configuration

- **Locked Architecture**: 6-Channel Early-Fusion Classical U-Net (`models/unet.py`)
- **Checkpoint Source**: [best_model.pth](file:///c:/Users/HP/Downloads/Forest%20Monitoring/AETHER-Deforestation/checkpoints/stage2b/best_model.pth) (Stage 2B Epoch 8)
- **Verified Parameter Count**: `31,039,361` (~31.04M)
- **Primary Operating Threshold**: **`0.25`** (Locked from Stage 2B validation sweep)
- **Evaluated Split**: Test Partition (`33` bi-temporal satellite image triplets, $480 \times 480$ resolution)
- **Execution Mode**: Analysis-Only (`model.eval()`, `torch.no_grad()`, zero weight updates)

---

## 3. Prediction Mask Generation

For each of the 33 test image triplets:
1. Satellite Image A (Before) and Image B (After) were loaded and normalized deterministically.
2. Concatenated along channel dimension $\rightarrow [1, 6, 480, 480]$ tensor.
3. Model forward pass $\rightarrow$ Raw Logit Map $\rightarrow$ Sigmoid $\rightarrow$ Probability Map.
4. Probability threshold applied:
   $$\text{Predicted Deforestation} = \begin{cases} 1 & \text{if Probability} \ge 0.25 \\ 0 & \text{if Probability} < 0.25 \end{cases}$$
5. Ground-Truth Mask threshold applied: $\text{GT Pixel} \ge 128 \rightarrow 1$, else $0$.

## 5. Deforestation Percentage Calculation

For every sample, deforestation area percentages and differences were calculated via:
$$\text{Predicted Deforestation \%} = \left(\frac{\text{Predicted Deforestation Pixels}}{\text{Total Image Pixels}}\right) \times 100$$
$$\text{Percentage Difference} = \text{Predicted Deforestation \%} - \text{Ground-Truth Deforestation \%}$$

The overall mean percentage difference was $+0.85\%$, confirming close alignment between predicted and ground-truth spatial density without catastrophic over-prediction or background collapse.

---

## 6. Connected Component Method (8-Connectivity)

Spatial region extraction was performed using a pure NumPy Two-Pass Disjoint-Set Union (DSU) algorithm enforcing **8-connectivity** (horizontal, vertical, and diagonal pixel adjacency).

For each extracted connected region, the following attributes were derived:
- **Region ID**: Integer index $(1 \dots N)$ per image
- **Pixel Count & Image Area Percentage**: Area occupied by component
- **Bounding Box Coordinates**: Pixel bounds $[x_{\min}, y_{\min}, x_{\max}, y_{\max}]$
- **Centroid Coordinates**: Spatial center $(\bar{x}, \bar{y})$

Full component metadata is exported to [deforestation_regions_stage4a.csv](file:///c:/Users/HP/Downloads/Forest%20Monitoring/AETHER-Deforestation/outputs/deforestation_regions_stage4a.csv).

> [!NOTE]

## 12. System Limitations

1. **Resolution Granularity**: Micro-clearing events $<5$ pixels ($<0.002\%$ of image) can be susceptible to edge noise.
2. **Boundary Smoothing**: Connected component bounding boxes approximate complex non-convex deforestation geometries into rectangular spatial bounds.

---

## 13. Physical Area Calculation Limitation

> [!CAUTION]
> **No Physical Unit Assumption**:
> Image array dimensions are $480 \times 480$ pixels. In the absence of calibrated ground sampling distance (GSD / meters per pixel) or georeferencing metadata, physical area units (such as $\text{km}^2$, hectares, or acres) are **strictly omitted** to avoid uncalibrated reporting. All metrics are expressed in exact pixel counts and image area percentages.
